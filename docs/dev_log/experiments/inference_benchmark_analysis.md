## 4. GPU 显存分析

### 原始测量值

| BS | 模型 | 峰值 GPU (MB) | 推理增量 (MB) | CPU RAM (MB) |
|:--:|:-----:|-------------:|-------------:|------------:|
| 1 | EEGNet | 15.7 | 6.3 | 0.00 |
| 1 | CBraMod | 132.2 | 5.9 | 0.01 |
| 8 | EEGNet | 62.8 | 52.0 | 0.00 |
| 8 | CBraMod | 177.3 | 47.6 | 0.01 |
| 32 | EEGNet | 215.9 | 200.5 | 0.00 |
| 32 | CBraMod | 330.8 | 189.0 | 0.01 |
| 64 | EEGNet | 422.7 | 401.0 | 0.00 |
| 64 | CBraMod | 537.1 | 380.0 | 0.01 |

> **推理增量** = 峰值显存 − 模型加载后基线显存，即纯推理过程产生的中间激活与临时缓冲区。

### 反直觉现象：为什么 CBraMod 的推理增量反而更低？

在 BS=64 时，CBraMod 的**推理增量**（380 MB）比 EEGNet（401 MB）**少了 21 MB**。一个 3000 万参数的 Transformer 居然比一个 1.6 万参数的 CNN 在推理过程中占用更少的中间显存——这看起来不合理，但实际上可以从两个模型的**中间张量生命周期**来解释。

#### EEGNet 的显存瓶颈：时域卷积层

EEGNet 的第一步是一个跨越全部 128 通道的时域卷积（`temporal_conv`），其输出尺寸为：

```
输入:  [64,  1, 128, 400]  =  12.5 MB
输出:  [64, 16, 128, 401]  = 200.5 MB   ← 峰值中间张量
```

这个 **200 MB 的特征图**是 EEGNet 整个推理过程中最大的单个张量。在执行下一步空间卷积（`spatial_conv`）时，输入和输出必须**同时驻留在显存中**：

```
temporal_conv 输出 (200.5 MB) + spatial_conv 输出 (6.3 MB) = ~207 MB 共存
```

再加上 cuDNN 卷积的 workspace 缓冲区、输入张量本身、以及各 BatchNorm 的临时统计量，总推理增量达到 **401 MB**。

空间卷积之后，张量从 `[64, 64, 128, 401]` 骤降到 `[64, 64, 1, 100]`（经过池化后仅 1.6 MB），但峰值已经在第一步形成了。

```
EEGNet 中间张量生命周期 (bs=64):

           ┌─── temporal_conv 输出: 200.5 MB ──────┐
           │                                        │
 12.5 MB ──┤          ┌── spatial_conv: 6.3 MB ─┐   ├── (freed)
 (input)   │          │                         │   │
           │          │   ┌── pool1: 1.6 MB     │   │
           └──────────┘   │                     └───┘
                          └── pool2: 0.2 MB ── fc: 0.002 MB
                                    ↓
                          Peak ≈ 213 MB (两个张量共存)
```

#### CBraMod 的显存模式：逐层释放

CBraMod 的 Criss-Cross Transformer 有 12 层，每层执行通道注意力和时间注意力。在 BS=64, 128 通道时：

```
通道注意力图: [64×5, 8, 128, 128]  = 160.0 MB / 层
时间注意力图: [64×128, 8, 5, 5]    =   6.2 MB / 层
                          合计      = 166.2 MB / 层
```

关键区别：这 166 MB 的注意力图在**每层计算完成后立即释放**，不会跨层累积。12 层 Transformer 的峰值显存不是 166 × 12 = 1994 MB，而是始终维持在 **~166 MB**（单层峰值）加上输入/输出张量：

```
CBraMod 显存时间线 (bs=64):

Layer 1:  input(31.2) + attn(166.2) + output(31.2) = ~228 MB peak
          → attn freed
Layer 2:  input(31.2) + attn(166.2) + output(31.2) = ~228 MB peak
          → attn freed
...
Layer 12: same pattern
Classifier: flattened(31.2) + hidden(0.05) = ~31 MB
```

#### 汇总解释

| 因素 | EEGNet | CBraMod |
|------|--------|---------|
| 最大单个中间张量 | **200.5 MB** (temporal_conv 输出) | **166.2 MB** (单层注意力图) |
| 该张量是否需要与其他大张量共存 | **是**（与 spatial_conv 输出共存） | **否**（逐层释放） |
| 输入张量大小 | 12.5 MB | 31.2 MB |
| cuDNN workspace 开销 | 较大（大卷积核） | 较小（矩阵乘法） |
| **实测推理增量** | **401 MB** | **380 MB** |

**结论**：EEGNet 的显存瓶颈源自一个**巨大且必须持久保留的特征图**（128 通道 × 16 滤波器 × 400 时间步）。CBraMod 虽然每层都产生大注意力图，但由于 Transformer 的**逐层顺序执行**特性，这些中间结果在计算完成后立即释放，峰值显存反而更低。

然而，CBraMod 的**峰值 GPU 总显存**（537 MB）仍高于 EEGNet（423 MB），因为模型权重本身占 116 MB（vs EEGNet 的 0.06 MB）。

## 5. 移动端与低算力设备部署可行性分析

### 硬件参考

| 平台 | 代表设备 | AI 算力 (FP16) | 内存 | 功耗 |
|------|---------|----------------|------|------|
| 旗舰手机 GPU | Snapdragon 8 Gen 3 (Adreno 750) | ~4.6 TFLOPS | 8-16 GB (共享) | ~10W |
| 中端手机 GPU | Snapdragon 7 Gen 1 (Adreno 644) | ~1.5 TFLOPS | 6-8 GB | ~5W |
| 手机 NPU | Snapdragon 8 Gen 3 (Hexagon) | ~45 TOPS (INT8) | 共享 | ~5W |
| 边缘设备 | NVIDIA Jetson Orin Nano | 20 TOPS (INT8) | 4-8 GB | 7-15W |
| 微控制器 | STM32H7 (Cortex-M7) | ~0.5 GOPS | 1 MB SRAM | ~0.5W |
| 桌面 GPU (本次测试) | RTX 5070 | ~500 TFLOPS (FP16) | 12 GB | 250W |

### EEGNet：可部署到几乎任何平台

| 指标 | FP32 | INT8 量化（估算） |
|------|------|-------------------|
| 模型大小 | 0.06 MB | ~0.02 MB |
| FLOPs | 112.7 MFLOPs | ~28.2 MOPs (INT8) |
| 推理内存 | ~6 MB (bs=1) | ~3 MB |
| 手机 GPU 延迟（估算） | < 0.1 ms | < 0.05 ms |
| MCU 延迟（估算） | ~200 ms | ~60 ms |

EEGNet 的 16K 参数和 113 MFLOPs 使其**甚至可以部署到微控制器级别**。通过 TensorFlow Lite Micro 或 ONNX Runtime Mobile，在 Cortex-M7 上也能实现亚秒级推理。对于手机和边缘设备，EEGNet 的推理延迟基本可以忽略不计。

### CBraMod：需要高端移动 GPU 或 NPU，但可行

| 指标 | FP32 | FP16 | INT8 量化（估算） |
|------|------|------|-------------------|
| 模型大小 | 116 MB | 58 MB | ~29 MB |
| FLOPs | 5.08 GFLOPs | 5.08 GFLOPs | ~1.27 GOPs |
| 推理内存 (bs=1) | ~132 MB | ~70 MB | ~40 MB |
| 旗舰手机 GPU 延迟（估算） | ~50 ms | ~5-10 ms | — |
| 手机 NPU 延迟（估算） | — | — | ~3-5 ms |
| Jetson Orin Nano 延迟（估算） | ~30 ms | ~15 ms | ~5 ms |

#### 挑战

1. **模型大小 (116 MB FP32)**：对于移动应用来说偏大，但 FP16 (58 MB) 或 INT8 (29 MB) 量化后在可接受范围内。作为参考，MobileNet V3 约 22 MB (FP32)，BERT-Base 约 440 MB。

2. **注意力图的内存开销**：128 通道 Criss-Cross Attention 在**单层**就需要 160 MB 的注意力图（bs=1 时约 2.5 MB）。在移动端需要：
   - 减少通道数（32ch 配置：注意力图缩小 16 倍至 10 MB/层）
   - 或使用线性注意力（linear attention）近似

3. **Transformer 对延迟不友好**：即使总 FLOPs 不高，12 层 Transformer 的**顺序依赖**（每层必须等前一层完成）导致无法深度流水线化。在 RTX 5070 上 bs=1 就需要 ~13 ms，在手机上会更明显。

4. **缺乏专用优化**：移动端 Transformer 推理尚缺乏类似 cuDNN 对卷积的成熟优化。ONNX Runtime、TFLite 对 Transformer 的支持在持续改进中，但效率不如 CNN。

#### 可行的优化路径

| 优化策略 | 预期效果 | 实施难度 |
|----------|---------|---------|
| FP16 推理 | 模型大小减半，延迟降低 30-50% | 低 — PyTorch 原生支持 |
| INT8 量化 (PTQ) | 模型大小缩至 1/4，NPU 可加速 | 中 — 需验证精度损失 |
| 减少通道数 (128→32) | FLOPs 降低 ~4x，注意力图缩小 16x | 低 — 项目已支持 32ch 配置 |
| 知识蒸馏 → 小模型 | 保留基座模型优势，大幅缩小 | 高 — 需要额外训练 |
| ONNX 导出 + 移动端 Runtime | 利用平台专属优化（NPU/DSP） | 中 — 需处理动态 shape |
| 层裁剪（12→6 层） | FLOPs 减半，精度需验证 | 中 — 需要微调 |

### 结论

| 维度 | EEGNet | CBraMod |
|------|--------|---------|
| 旗舰手机 (FP16) | **轻松** — < 1 ms | **可行** — 预计 5-10 ms |
| 中端手机 | **轻松** — < 1 ms | **勉强** — 预计 20-50 ms |
| 低端/IoT 设备 | **可行** — < 500 ms | **不可行** — 内存不足 |
| 微控制器 | **勉强可行** | **不可行** |
| 实时 BCI (< 100 ms) | 全平台达标 | 仅桌面 GPU 和旗舰手机达标 |

**CBraMod 在旗舰手机上可以运行**，特别是经过 FP16/INT8 量化和通道数缩减后。但如果目标是低功耗可穿戴 BCI 设备，EEGNet 是唯一现实的选择——其 16K 参数在任何硬件上都可以实时运行，而 CBraMod 的 Transformer 架构天然不适合极端低功耗场景。

对于**实用 BCI 产品**的推荐路线：使用 CBraMod 在云端/桌面端训练，然后通过**知识蒸馏**将学到的 EEG 表征迁移到 EEGNet 级别的轻量模型上进行端侧推理。这样可以同时获得基座模型的解码精度优势和 CNN 的部署效率。
